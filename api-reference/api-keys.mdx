The API Keys resource lets you programmatically create and manage the credentials used to authenticate requests to the Amplify API. Each key can optionally be scoped to a specific set of permissions, limiting what the key can do even if the creating user has broader access. The raw key value is returned only once — at creation time — so store it securely in an environment variable or secrets manager immediately after creating it.

<Note>
  The full interactive reference for this resource is generated from the Amplify OpenAPI spec. The endpoints and parameters below reflect the current public API surface.
</Note>

<Warning>
  The `key` value is returned **only once**, in the response to `POST /v1/api-keys`. It cannot be retrieved again via the API. Store it in an environment variable or secrets manager immediately after creation. If you lose the key, revoke it and create a new one.
</Warning>

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/api-keys` | Create an API key |
| `GET` | `/v1/api-keys` | List API keys |
| `GET` | `/v1/api-keys/{id}` | Get an API key |
| `DELETE` | `/v1/api-keys/{id}` | Revoke an API key |

## POST /v1/api-keys

Create a new API key. Amplify returns the key value exactly once in the creation response — it cannot be retrieved again. Copy it to a secure location immediately.

### Request body

<ParamField body="name" type="string" required>
  A descriptive name to identify the key's purpose or the application using it (e.g., `Production App`, `CI/CD Pipeline`).
</ParamField>

<ParamField body="permissions" type="array">
  Optional array of permission strings to scope this key's access. When omitted, the key inherits the full permissions of the creating user. Providing an explicit list restricts the key to only those actions.

  <Expandable title="Example permission strings">
    Permission strings follow the `resource:action` format. For example: `faxes:read`, `faxes:write`, `messages:read`, `messages:write`, `esign:read`, `esign:write`, `documents:read`, `documents:write`, `contacts:read`, `contacts:write`.
  </Expandable>
</ParamField>

### Code example

<CodeGroup>

```bash cURL
curl -X POST https://api.amplify.xyz/v1/api-keys \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production Fax Service",
    "permissions": ["faxes:read", "faxes:write"]
  }'
```

```javascript Node.js
const response = await fetch("https://api.amplify.xyz/v1/api-keys", {
  method: "POST",
  headers: {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    name: "Production Fax Service",
    permissions: ["faxes:read", "faxes:write"],
  }),
});

const { data } = await response.json();
// Store data.key immediately — it will not be returned again
console.log(data.key);
```

</CodeGroup>

### Response

<ResponseField name="id" type="string">
  Unique identifier for the API key, prefixed with `key_`.
</ResponseField>

<ResponseField name="name" type="string">
  The descriptive name assigned to this key.
</ResponseField>

<ResponseField name="key" type="string">
  The raw API key value. **Returned only in this creation response.** Store it securely now — it cannot be retrieved again via the API.
</ResponseField>

<ResponseField name="permissions" type="array">
  Array of permission strings assigned to this key. `null` if the key has full (unscoped) access.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the key was created.
</ResponseField>

### Example response

```json
{
  "data": {
    "id": "key_01HZOP5QTUV6W0FZRY8U1DKJH",
    "name": "Production Fax Service",
    "key": "ampl_live_xK9mR3pQnW7vYtBz2dLcSgJeUf6HiAoN",
    "permissions": ["faxes:read", "faxes:write"],
    "created_at": "2024-06-01T12:00:00Z",
    "last_used_at": null
  }
}
```

<Warning>
  The `key` value is shown only once, at creation time. If you lose it, revoke the key and create a new one. Never commit API keys to source control.
</Warning>

## GET /v1/api-keys

Retrieve a paginated list of all API keys on your account. The `key` value is never included in list responses — only the `id`, `name`, and metadata are returned.

### Query parameters

<ParamField query="limit" type="integer">
  Number of results per page. Defaults to `20`, maximum `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from `meta.next_cursor` in the previous response.
</ParamField>

### Code example

```bash cURL
curl https://api.amplify.xyz/v1/api-keys \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## GET /v1/api-keys/{id}

Retrieve metadata for a single API key. The raw `key` value is never returned by this endpoint.

### Path parameters

<ParamField path="id" type="string" required>
  The unique identifier of the API key.
</ParamField>

### Response fields

<ResponseField name="id" type="string">
  Unique identifier for the API key.
</ResponseField>

<ResponseField name="name" type="string">
  Descriptive name of the key.
</ResponseField>

<ResponseField name="key" type="string">
  Always `null` on this endpoint. The key value is only returned at creation time.
</ResponseField>

<ResponseField name="permissions" type="array">
  Array of permission strings scoped to this key. `null` if the key has full access.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the key was created.
</ResponseField>

<ResponseField name="last_used_at" type="string">
  ISO 8601 timestamp of the most recent authenticated request made using this key. `null` if the key has never been used.
</ResponseField>

### Example response

```json
{
  "data": {
    "id": "key_01HZOP5QTUV6W0FZRY8U1DKJH",
    "name": "Production Fax Service",
    "key": null,
    "permissions": ["faxes:read", "faxes:write"],
    "created_at": "2024-06-01T12:00:00Z",
    "last_used_at": "2024-06-03T08:45:22Z"
  }
}
```

## DELETE /v1/api-keys/{id}

Revoke an API key immediately. Any requests using the revoked key will immediately begin receiving `401 Unauthorized` responses. This action cannot be undone — create a new key if programmatic access is still needed.

### Path parameters

<ParamField path="id" type="string" required>
  The unique identifier of the API key to revoke.
</ParamField>

<Warning>
  Revoking a key takes effect immediately and cannot be reversed. Ensure you have updated all applications using the key before revoking it to avoid service disruption.
</Warning>

<Tip>
  Use the `last_used_at` field from `GET /v1/api-keys/{id}` to determine whether a key is still actively in use before revoking it.
</Tip>
