The Amplify API is a REST API served exclusively over HTTPS. Every request targets the base URL `https://api.amplify.xyz/v1`, accepts JSON request bodies, and returns JSON responses. You authenticate each request with an API key passed as a Bearer token in the `Authorization` header. All endpoints follow consistent conventions for pagination, error shapes, and rate limiting so that patterns you learn in one resource apply everywhere else in the API.

## Base URL

```
https://api.amplify.xyz/v1
```

All paths in this reference are relative to this base URL. For example, `POST /v1/faxes` means a `POST` request to `https://api.amplify.xyz/v1/faxes`.

## Authentication

Pass your API key as a Bearer token on every request:

```http
access_token: YOUR_API_KEY
```

<Warning>
  Never embed API keys in client-side code or public repositories. Use environment variables or a secrets manager to inject keys at runtime.
</Warning>

Generate and revoke API keys from the Amplify dashboard. See [Authentication](/platform/authentication) for a full guide.

## Request Format

For requests that include a body (`POST`, `PATCH`, `PUT`), set the `Content-Type` header to `application/json` and send a valid JSON object:

```http
Content-Type: application/json
```

Multipart requests (for example, uploading a document file) use `Content-Type: multipart/form-data` instead — individual endpoint pages note when this applies.

## Response Envelope

Every response body is a JSON object. Successful responses follow this envelope:

<ResponseField name="data" type="object | array">
  The primary resource or array of resources returned by the request.
</ResponseField>

<ResponseField name="meta" type="object">
  Metadata about the response, such as pagination cursors and total counts. Present on list endpoints.
</ResponseField>

<ResponseField name="meta.total" type="integer">
  Total number of records matching the query across all pages.
</ResponseField>

<ResponseField name="meta.next_cursor" type="string">
  Opaque cursor to pass as `cursor` on the next request to fetch the following page. `null` when you are on the last page.
</ResponseField>

### Example success response

```json
{
  "data": {
    "id": "fx_01HZ9K2MXQR4T7BVNW3P6YJCE",
    "status": "delivered",
    "to": "+14155550100",
    "from": "+18005550199",
    "pages": 2,
    "created_at": "2024-06-01T12:00:00Z",
    "updated_at": "2024-06-01T12:04:32Z"
  }
}
```

## Error Format

When a request fails, the API returns an appropriate HTTP status code and a JSON body with the following shape:

<ResponseField name="error" type="object">
  Top-level error container.
</ResponseField>

<ResponseField name="error.code" type="string">
  A machine-readable error code string, such as `invalid_parameter` or `not_found`.
</ResponseField>

<ResponseField name="error.message" type="string">
  A human-readable description of what went wrong.
</ResponseField>

<ResponseField name="error.param" type="string">
  The request parameter that caused the error, when applicable.
</ResponseField>

### Example error response

```json
{
  "error": {
    "code": "invalid_parameter",
    "message": "The 'to' field must be a valid E.164 phone number.",
    "param": "to"
  }
}
```

### HTTP status codes

| Status | Meaning |
|--------|---------|
| `200 OK` | Request succeeded. |
| `201 Created` | Resource was created successfully. |
| `204 No Content` | Request succeeded with no response body (e.g., DELETE). |
| `400 Bad Request` | The request was malformed or missing required parameters. |
| `401 Unauthorized` | The API key is missing or invalid. |
| `403 Forbidden` | The API key does not have permission for this action. |
| `404 Not Found` | The requested resource does not exist. |
| `409 Conflict` | The request conflicts with the current state of the resource. |
| `422 Unprocessable Entity` | The request was well-formed but contains semantic errors. |
| `429 Too Many Requests` | You have exceeded the rate limit. |
| `500 Internal Server Error` | An unexpected error occurred on Amplify's servers. |

See [Error Handling](/platform/errors) for the full list of error codes and retry guidance.

## Pagination

List endpoints return paginated results using cursor-based pagination. Pass the `cursor` query parameter to fetch the next page:

```http
GET /v1/faxes?limit=25&cursor=NEXT_CURSOR_VALUE
```

<Tip>
  Use `limit` to control page size (default 20, maximum 100). Always check `meta.next_cursor` — when it is `null`, you have reached the last page.
</Tip>

See [Pagination](/platform/pagination) for a complete walkthrough with code examples.

## Rate Limits

Requests are rate-limited per API key. When you exceed the limit the API returns `429 Too Many Requests` with a `Retry-After` header indicating how many seconds to wait before retrying.

See [Rate Limits](/platform/rate-limits) for per-endpoint limits and burst allowances.
