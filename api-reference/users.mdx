The Users resource provides read and update access to the team member accounts on your Amplify organization. Each user has a name, email address, and an assigned role that determines their access level. Use this resource to list all users in your organization, retrieve a specific user's profile, and update user properties such as their role or display name. User invitations and account deletion are managed through the Amplify dashboard.

## GET /v1/users

Retrieve a paginated list of all active users in your Amplify organization.

### Query parameters

<ParamField query="limit" type="integer">
  Number of results per page. Defaults to `20`, maximum `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Pagination cursor from `meta.next_cursor` in the previous response.
</ParamField>

<ParamField query="search" type="string">
  Filter users by name or email using a partial string match.
</ParamField>

<ParamField query="role" type="string">
  Filter by user role (e.g., `admin`, `member`).
</ParamField>

### Code example

```bash cURL
curl https://api.amplify.xyz/v1/users \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## PATCH /v1/users/{id}

Update a user's profile or role. Only include fields you want to change.

### Path parameters

<ParamField path="id" type="string" required>
  The unique identifier of the user to update.
</ParamField>

### Request body

<ParamField body="name" type="string">
  Updated display name for the user.
</ParamField>

<ParamField body="role" type="string">
  Updated role assignment. Changing a user's role takes effect immediately.
</ParamField>

<ParamField body="permission_group_id" type="string">
  ID of the permission group to assign. Pass `null` to remove the user from any permission group.
</ParamField>

### Code example

```bash cURL
curl -X PATCH https://api.amplify.xyz/v1/users/usr_01HZKH1MRST4U8DXQW6S9BHIF \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "role": "member"
  }'
```

<Warning>
  Changing your own role may reduce your own access permissions. Ensure at least one other admin exists in your organization before downgrading your own account.
</Warning>
