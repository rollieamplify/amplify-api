Exchange your Amplify API key for an access token, then send that token in the standard `Authorization` header using the `Bearer` scheme. Keep both credentials secure and rotate them any time you suspect they have been compromised.

## Generate an API Key

Log in to the Amplify dashboard at [https://app.amplify.xyz](https://app.amplify.xyz). Navigate to **Settings → API Keys** and click **Create API Key**. Provide a descriptive label (for example, the name of the service or environment that will use the key) and click **Generate**.

Amplify displays the full key exactly once at creation time. Copy it and store it somewhere safe — such as your password manager or secrets vault — before closing the dialog. If you lose the key, you must revoke it and generate a new one.

### API Key Format

Production API keys follow this format:

```text
YOUR_ACCESS_TOKEN
```

Use the access token generated for your Amplify account.

## Pass the access token in requests

Include your token in the `Authorization` header on every request:

```text
Authorization: Bearer YOUR_ACCESS_TOKEN
```

The examples below show how to set this header in curl, Python, and Node.js.

<CodeGroup>
  ```bash curl
  curl https://api.amplify.xyz/v1/faxes \
    -H "Authorization: Bearer $AMPLIFY_ACCESS_TOKEN"
  ```

  ```python Python
  import os
  import requests

  api_key = os.environ["AMPLIFY_ACCESS_TOKEN"]

  response = requests.get(
      "https://api.amplify.xyz/v1/faxes",
      headers={"Authorization": f"Bearer {access_token}"}
  )
  print(response.json())
  ```

  ```javascript Node.js
  const apiKey = process.env.AMPLIFY_ACCESS_TOKEN;

  const response = await fetch("https://api.amplify.xyz/v1/faxes", {
    headers: {
      "Authorization": `Bearer ${accessToken}`
    }
  });
  const data = await response.json();
  console.log(data);
  ```
</CodeGroup>

<Warning>
  Never expose your API key in client-side code (browser JavaScript, mobile apps), public repositories, or anywhere it could be read by third parties. Use server-side code or a secure backend proxy to make Amplify API calls on behalf of your users. Rotate any key you suspect has been exposed immediately.
</Warning>

## Authentication Failures

When a request is missing its Bearer token, uses a malformed token, or uses a token that has expired or been revoked, the API returns an HTTP `401 Unauthorized` response with a JSON error body:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid or missing API key."
  }
}
```

Check the following if you receive a `401`:

- Confirm the `Authorization` header uses the format `Bearer YOUR_ACCESS_TOKEN`.
- Confirm the access token has not been truncated.
- Verify the key has not been revoked in the dashboard under **Settings → API Keys**.

<Note>
  You can revoke or rotate any API key at any time from the dashboard under **Settings → API Keys**. Revoking a key takes effect immediately — any request using a revoked key will receive a `401` response. Create a replacement key before revoking the old one to avoid downtime.
</Note>

## Best Practices

<Tip>
  Store your API key as an environment variable (e.g., `AMPLIFY_ACCESS_TOKEN`) rather than hard-coding it in your application. Reference the variable in your code and inject it through your deployment pipeline or secrets manager.
</Tip>

- **Use one key per environment.** Create separate keys for development, staging, and production so you can rotate or revoke them independently.
- **Limit key scope to what you need.** If Amplify introduces scoped permissions in the future, request only the permissions your integration requires.
- **Audit key usage.** Review the API Keys page in the dashboard periodically and revoke any keys that are no longer in use.
- **Rotate keys on a schedule.** Even without a known compromise, rotating keys regularly reduces the window of exposure if a key is ever leaked.
