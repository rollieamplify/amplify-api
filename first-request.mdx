This guide walks you through the full lifecycle of a fax request using the Amplify API: list existing faxes to verify your credentials, send a new fax, and then poll for its delivery status. By the end, you'll understand the core request-response pattern used across every Amplify product area. The same shape — create a resource, get an ID back, check its status — applies to eSign envelopes, outbound calls, document generation, and more.

## Prerequisites

Before you begin, make sure you have an active Amplify API key. If you haven't generated one yet, follow the [Authentication guide](/authentication) to create a key and learn how to pass it securely in your requests.

<Steps>
  <Step title="List faxes to verify authentication">
    Start by sending a `GET /v1/faxes` request. This confirms your API key is valid and gives you a baseline look at the faxes resource shape before you create one.

    <CodeGroup>
      ```bash curl
      curl https://api.amplify.xyz/v1/faxes \
        -H "Authorization: Bearer ak_live_..."
      ```

      ```javascript Node.js
      const response = await fetch("https://api.amplify.xyz/v1/faxes", {
        headers: {
          "Authorization": "Bearer ak_live_..."
        }
      });
      const data = await response.json();
      console.log(data);
      ```
    </CodeGroup>

    A successful response returns HTTP `200 OK` with a paginated list of fax objects. On a new account the `data` array will be empty, which is completely normal.

    ```json
    {
      "data": [],
      "meta": {
        "total": 0,
        "page": 1,
        "per_page": 20
      }
    }
    ```

    If you receive a `401 Unauthorized`, revisit the [Authentication guide](/authentication) to check your header format and confirm the key has not been revoked.
  </Step>

  <Step title="Send a test fax">
    Send a `POST /v1/faxes` request with a recipient number, a sender number, and a publicly accessible URL pointing to the PDF document you want to fax. Amplify fetches the document from the URL, converts it if necessary, and transmits it to the recipient.

    <CodeGroup>
      ```bash curl
      curl -X POST https://api.amplify.xyz/v1/faxes \
        -H "Authorization: Bearer ak_live_..." \
        -H "Content-Type: application/json" \
        -d '{
          "to": "+15551234567",
          "from": "+15557654321",
          "document_url": "https://example.com/document.pdf"
        }'
      ```

      ```javascript Node.js
      const response = await fetch("https://api.amplify.xyz/v1/faxes", {
        method: "POST",
        headers: {
          "Authorization": "Bearer ak_live_...",
          "Content-Type": "application/json"
        },
        body: JSON.stringify({
          to: "+15551234567",
          from: "+15557654321",
          document_url: "https://example.com/document.pdf"
        })
      });
      const fax = await response.json();
      console.log(fax);
      ```
    </CodeGroup>

    The `to` and `from` fields accept E.164-formatted phone numbers. The `from` number must be a fax-capable number provisioned on your Amplify account. The `document_url` must be publicly accessible over HTTPS at the time Amplify processes the request.

    A successful response returns HTTP `201 Created` with the new fax object in its initial `queued` state:

    ```json
    {
      "id": "fax_01hx4k9mzq3r7vbn2cwtpdjfe8",
      "status": "queued",
      "to": "+15551234567",
      "from": "+15557654321",
      "document_url": "https://example.com/document.pdf",
      "created_at": "2024-01-15T10:30:00Z"
    }
    ```

    Save the `id` field from the response — you'll use it in the next step to check delivery status.

    <Note>
      Fax transmission is asynchronous. The API acknowledges your request immediately and returns a `queued` status. The actual transmission happens in the background and the status advances through `sending` to either `delivered` or `failed`.
    </Note>
  </Step>

  <Step title="Check the fax status">
    Use the fax `id` from the previous step to retrieve the current status of your fax with a `GET /v1/faxes/{id}` request.

    <CodeGroup>
      ```bash curl
      curl https://api.amplify.xyz/v1/faxes/fax_01hx4k9mzq3r7vbn2cwtpdjfe8 \
        -H "Authorization: Bearer ak_live_..."
      ```

      ```javascript Node.js
      const faxId = "fax_01hx4k9mzq3r7vbn2cwtpdjfe8";

      const response = await fetch(
        `https://api.amplify.xyz/v1/faxes/${faxId}`,
        {
          headers: {
            "Authorization": "Bearer ak_live_..."
          }
        }
      );
      const fax = await response.json();
      console.log(fax.status);
      ```
    </CodeGroup>

    The response includes the full fax object with the current `status` field:

    ```json
    {
      "id": "fax_01hx4k9mzq3r7vbn2cwtpdjfe8",
      "status": "delivered",
      "to": "+15551234567",
      "from": "+15557654321",
      "pages": 2,
      "duration_seconds": 47,
      "created_at": "2024-01-15T10:30:00Z",
      "completed_at": "2024-01-15T10:31:45Z"
    }
    ```

    Possible values for `status` are:

    | Status | Meaning |
    |---|---|
    | `queued` | Accepted and waiting to be processed |
    | `sending` | Transmission is actively in progress |
    | `delivered` | Successfully delivered to the recipient |
    | `failed` | Transmission failed; check `failure_reason` for details |

    <Warning>
      Avoid polling the status endpoint more frequently than once every 5 seconds. For production workloads, use webhooks to receive real-time status updates pushed to your server instead of polling.
    </Warning>
  </Step>
</Steps>

<Tip>
  The request lifecycle you followed here — create a resource, receive an ID, check status — is consistent across all Amplify product areas. Try the same pattern with eSign envelopes (`POST /v1/envelopes`), outbound calls (`POST /v1/calls`), or document generation jobs (`POST /v1/documents`).
</Tip>
