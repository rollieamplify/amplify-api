After you send a fax, Amplify moves it through a series of status states as it progresses from queuing through transmission to final delivery. Understanding the fax lifecycle lets you build reliable workflows that react correctly to successful deliveries, transient failures, and permanent errors.

## Fax status values

| Status | Description |
|---|---|
| `queued` | The fax has been accepted and is waiting to be sent. |
| `sending` | Amplify is actively transmitting the fax to the recipient. |
| `delivered` | The recipient's fax machine confirmed successful receipt. |
| `failed` | Transmission failed after all retry attempts were exhausted. |
| `cancelled` | The fax was cancelled before transmission began. |

Faxes move forward through `queued → sending → delivered` on success, or `queued → sending → failed` when all attempts are unsuccessful. A fax in the `queued` state can also transition directly to `cancelled` if you cancel it before transmission starts.

## Option 1: Poll for status

You can check the current status of any fax at any time by making a `GET` request to `/v1/faxes/{id}`. This is useful for one-off checks or low-volume workflows.

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.amplify.xyz/v1/faxes/fax_01hx... \
  --header 'Authorization: Bearer YOUR_API_KEY'
```

```python Python
import requests

fax_id = "fax_01hx..."

response = requests.get(
    f"https://api.amplify.xyz/v1/faxes/{fax_id}",
    headers={"Authorization": "Bearer YOUR_API_KEY"},
)

fax = response.json()
print(fax["status"])  # e.g. delivered
```

```javascript Node.js
const faxId = "fax_01hx...";

const response = await fetch(
  `https://api.amplify.xyz/v1/faxes/${faxId}`,
  {
    headers: { Authorization: "Bearer YOUR_API_KEY" },
  }
);

const fax = await response.json();
console.log(fax.status); // e.g. delivered
```

</CodeGroup>

#### Example response

```json
{
  "id": "fax_01hx...",
  "status": "delivered",
  "to": "+15551234567",
  "from": "+15557654321",
  "pages": 3,
  "created_at": "2024-01-15T10:30:00Z",
  "updated_at": "2024-01-15T10:34:12Z"
}
```

<Warning>
  Avoid polling more frequently than once every 10 seconds. Aggressive polling can cause rate limiting on your API key and slows down delivery for other requests in your account.
</Warning>

## Option 2: Use webhooks for real-time updates

For production workflows, webhooks are the recommended way to track fax status. Amplify pushes an event to your endpoint the moment a fax status changes, eliminating the need to poll repeatedly.

Subscribe to these events in your webhook configuration:

| Event | Triggered when |
|---|---|
| `fax.delivered` | The fax was successfully delivered to the recipient. |
| `fax.failed` | All transmission attempts have failed. |

<Tip>
  Webhooks are more efficient and lower-latency than polling. They also reduce your API usage and simplify your application logic — you react to state changes as they happen instead of managing a polling loop. See [Webhooks Overview](/platform/webhooks/overview) to configure your endpoint.
</Tip>

## Handling failures

When a fax transitions to `failed`, the fax object includes an `error` field with a machine-readable code and a human-readable message.

```json
{
  "id": "fax_01hx...",
  "status": "failed",
  "error": {
    "code": "no_answer",
    "message": "The recipient fax machine did not answer after 3 attempts."
  }
}
```

Common error codes and recommended actions:

| Error code | Meaning | Recommended action |
|---|---|---|
| `no_answer` | Recipient did not answer | Retry after a delay or verify the number |
| `busy` | Line was busy during all attempts | Retry at a different time |
| `invalid_number` | The `to` number is not a valid fax number | Verify the destination number |
| `document_error` | Amplify could not retrieve or render the document | Check the `document_url` and file format |

For transient errors such as `no_answer` or `busy`, submit a new fax request with the same parameters after a waiting period. For permanent errors such as `invalid_number`, correct the underlying issue before retrying.
