Every request you make to the Amplify API must include a valid API key. The API uses key-based authentication — there are no sessions, cookies, or OAuth flows to manage. You attach your key to each request via the `Authorization` header, and the API validates it before processing anything.

## Generate an API Key

To create a new API key, open the [Amplify dashboard](https://app.amplify.xyz), navigate to **Settings → API Keys**, and click **Create API Key**. Give the key a descriptive name (for example, `production-server` or `staging-integration`) so you can identify it later. After creation, copy the key immediately — it will not be shown again.

All Amplify API keys follow this format:

```text
ak_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Store this value securely before closing the dialog.

## Pass Your Key in Requests

Include your API key in the `Authorization` header of every request using the `Bearer` scheme:

```http
Authorization: Bearer ak_live_...
```

The following examples show how to authenticate requests across common HTTP clients:

<CodeGroup>

```bash curl
curl https://api.amplify.xyz/v1/faxes \
  -H "Authorization: Bearer ak_live_..."
```

```python Python
import os
import requests

response = requests.get(
    "https://api.amplify.xyz/v1/faxes",
    headers={
        "Authorization": f"Bearer {os.environ['AMPLIFY_API_KEY']}"
    }
)

data = response.json()
```

```javascript Node.js
import fetch from "node-fetch";

const response = await fetch("https://api.amplify.xyz/v1/faxes", {
  headers: {
    Authorization: `Bearer ${process.env.AMPLIFY_API_KEY}`,
  },
});

const data = await response.json();
```

</CodeGroup>

## Security Best Practices

Treat your API key like a password. Follow these practices to keep your integration secure:

- **Use environment variables.** Never hard-code your API key in source files. Read it from an environment variable (for example, `process.env.AMPLIFY_API_KEY`) or a secrets manager at runtime.
- **Keep keys server-side.** Only use your API key in server-side code — never in browser JavaScript, mobile apps, or any environment where end users can inspect the source.
- **Rotate keys regularly.** Generate a new key periodically and update your applications. This limits the exposure window if a key is ever leaked.
- **Revoke compromised keys immediately.** If you suspect a key has been exposed, go to **Settings → API Keys** in the dashboard and click **Revoke** next to the affected key. Create a replacement key and deploy it before revoking the old one if you need zero downtime.
- **Use separate keys per environment.** Maintain distinct keys for development, staging, and production so a leaked development key cannot affect production data.

<Warning>
Never embed your API key in client-side code, public repositories, or build artifacts. Anyone who obtains your key can make authenticated API calls on your behalf, including sending faxes, accessing documents, and modifying account settings. If you accidentally commit a key to a public repository, revoke it immediately regardless of whether you have already removed it from the commit history.
</Warning>

## Authentication Error Responses

When a request fails authentication, the API returns one of two status codes:

| Status Code | When It Occurs |
|---|---|
| `401 Unauthorized` | The `Authorization` header is missing, malformed, or contains an invalid or revoked key. |
| `403 Forbidden` | The key is valid, but it does not have permission to perform the requested operation. |

Both responses follow the [standard error envelope](/platform/errors):

```json
{
  "error": {
    "code": "unauthorized",
    "message": "No valid API key provided."
  }
}
```

If you receive a `401`, verify that your key is correctly formatted and has not been revoked. If you receive a `403`, check that the key you are using has the necessary permissions for the endpoint you are calling.
