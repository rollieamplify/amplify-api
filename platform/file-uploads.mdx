Several Amplify API endpoints accept file attachments — for example, attaching a PDF to a fax send request or uploading a document template for e-signature. You have two ways to provide a file: reference it by URL or upload it directly as multipart form data. Choose the method that fits your workflow best.

## Supported File Formats and Size Limits

The following file types are accepted across Amplify endpoints that support attachments:

| Format | MIME Type | Common Use |
|---|---|---|
| PDF | `application/pdf` | Fax documents, e-sign templates |
| DOCX | `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | Document templates |
| PNG | `image/png` | Images, fax cover pages |
| JPEG | `image/jpeg` | Images, fax cover pages |
| TIFF | `image/tiff` | Scanned fax documents |

The maximum file size is **25 MB per file**. Requests that include a file exceeding this limit return a `422 Unprocessable Entity` response.

## Method 1: URL Reference

Pass a publicly accessible URL in your request body using the `document_url` field (or the equivalent field for the endpoint you are calling). Amplify fetches the file from the URL at request time.

```json
{
  "to": "+15550001234",
  "document_url": "https://example.com/document.pdf"
}
```

This is the simplest approach when your files are already hosted somewhere accessible, such as an S3 bucket, a CDN, or a document management system.

<Warning>
The URL you provide must be publicly accessible without authentication. Amplify's servers fetch the file directly, so URLs behind a login, a VPN, or an HTTP `Authorization` header will fail. If your files are stored in a private bucket, generate a pre-signed URL with a sufficient expiry window (at least a few minutes) before passing it to the API.
</Warning>

## Method 2: Multipart Upload

Upload the file directly in the request body using `multipart/form-data`. Set the `Content-Type` header to `multipart/form-data` (most HTTP clients handle this automatically when you use form fields).

<CodeGroup>

```bash curl
curl https://api.amplify.xyz/v1/documents \
  -H "Authorization: Bearer ak_live_..." \
  -F "file=@/path/to/document.pdf" \
  -F "name=My Document"
```

```javascript Node.js
import fetch from "node-fetch";
import fs from "fs";
import FormData from "form-data";

const form = new FormData();
form.append("file", fs.createReadStream("/path/to/document.pdf"), {
  filename: "document.pdf",
  contentType: "application/pdf",
});
form.append("name", "My Document");

const response = await fetch("https://api.amplify.xyz/v1/documents", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.AMPLIFY_API_KEY}`,
    ...form.getHeaders(),
  },
  body: form,
});

const document = await response.json();
console.log("Uploaded document ID:", document.id);
```

</CodeGroup>

After a successful multipart upload, the response includes the uploaded document's resource ID, which you can then reference in subsequent API calls.

## Comparison: URL Reference vs. Multipart Upload

| | URL Reference | Multipart Upload |
|---|---|---|
| **File location** | Already hosted externally | Local filesystem or in-memory buffer |
| **Simplicity** | Simpler — one JSON field | Requires form encoding |
| **Large files** | Recommended for large files | Works up to 25 MB limit |
| **Private files** | Requires pre-signed URL | Upload directly without exposing files |

<Tip>
For large files approaching the 25 MB limit, prefer the URL reference method using a pre-signed URL from your storage provider (for example, AWS S3 or Google Cloud Storage). Pre-signed URLs give Amplify temporary, authenticated access to a private object without requiring you to make the file permanently public. Set the URL expiry to at least 10 minutes to account for any processing delay.
</Tip>
