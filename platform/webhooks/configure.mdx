Before Amplify can send events to your application, you need to register a webhook endpoint. You can do this through the dashboard in a few clicks or programmatically using the REST API. Either way, Amplify generates a unique signing secret for each endpoint you create — keep that secret safe, because you'll use it to verify every incoming request.

## Configure via the Dashboard

The dashboard is the fastest way to register a new endpoint and choose which events to subscribe to.

<Steps>
  <Step title="Open the Webhooks settings">
    Log in to the Amplify dashboard, navigate to **Settings**, then select **Webhooks**. Click **Add Endpoint** to open the registration form.
  </Step>
  <Step title="Enter your endpoint URL">
    Type the full URL of your webhook receiver in the **Endpoint URL** field. The URL must use HTTPS — Amplify does not deliver events to plain HTTP endpoints.
  </Step>
  <Step title="Select your event subscriptions">
    Choose one or more event types from the list. You can subscribe to individual events such as `fax.delivered` or select an entire product group to capture all related events. See [Event Types](/platform/webhooks/event-types) for the full list.
  </Step>
  <Step title="Save and copy your signing secret">
    Click **Save**. Amplify creates the endpoint and displays your **signing secret** once. Copy it and store it securely — it will not be shown again.
  </Step>
  <Step title="Verify incoming requests">
    Use the signing secret in your application to validate the `Amplify-Signature` header on every incoming webhook request. Follow the steps in [Verify Webhook Signatures](/platform/webhooks/authentication) to implement this correctly.
  </Step>
</Steps>

<Note>
  Amplify only delivers webhooks to HTTPS endpoints. Make sure your server presents a valid TLS certificate from a trusted certificate authority. Self-signed certificates are not accepted.
</Note>

## Configure via the API

If you prefer to manage endpoints programmatically — for example, in an infrastructure-as-code workflow or during automated testing — use the `POST /v1/webhooks` endpoint.

### Create an Endpoint

Send a `POST` request to `https://api.amplify.xyz/v1/webhooks` with the endpoint URL and the list of events you want to subscribe to.

<CodeGroup>
```bash cURL
curl -X POST https://api.amplify.xyz/v1/webhooks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://yourapp.com/webhooks/amplify",
    "events": ["fax.delivered", "fax.failed", "esign.completed"]
  }'
```

```json Request Body
{
  "url": "https://yourapp.com/webhooks/amplify",
  "events": ["fax.delivered", "fax.failed", "esign.completed"]
}
```
</CodeGroup>

### Response

A successful request returns `201 Created` with the new endpoint object. The `signing_secret` field is included in this response only — it cannot be retrieved again after creation.

```json
{
  "id": "wh_01hx...",
  "url": "https://yourapp.com/webhooks/amplify",
  "events": ["fax.delivered", "fax.failed", "esign.completed"],
  "signing_secret": "whsec_...",
  "created_at": "2024-01-15T10:30:00Z"
}
```

<Warning>
  The `signing_secret` is returned **only once** at creation time. Store it immediately in a secure secrets manager such as AWS Secrets Manager, HashiCorp Vault, or your platform's equivalent environment variable store. If you lose it, you must delete the endpoint and create a new one.
</Warning>

## Manage Existing Endpoints

You can list, update, and delete webhook endpoints at any time.

| Action | Method | Path |
|---|---|---|
| List all endpoints | `GET` | `/v1/webhooks` |
| Retrieve an endpoint | `GET` | `/v1/webhooks/{id}` |
| Update an endpoint | `PATCH` | `/v1/webhooks/{id}` |
| Delete an endpoint | `DELETE` | `/v1/webhooks/{id}` |

For full request and response schemas, refer to the [Webhooks API Reference](/api-reference/webhooks).
